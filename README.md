# سايبر العراق — المراحل 1 إلى 6 (كاملة)

## المرحلة 4 (المدرس الذكي + الإشعارات)

- تطبيق المستخدم: شاشة محادثة مع المدرس الذكي (زر عائم بالشاشة الرئيسية)، كل رسالة تمر عبر Edge Function `ai-tutor` فقط — لا يوجد أي مفتاح API داخل التطبيق. تُعرض رسائل واضحة عند تجاوز الحد اليومي أو تعطيل الميزة من الإدارة.
- تطبيق الإدارة: شاشة "إدارة المدرس الذكي" (تفعيل/تعطيل الميزة عبر `app_settings.ai_tutor_enabled`، ومراقبة عدد الرسائل اليوم والإجمالي من `ai_usage_logs` — بدون تخزين أي محتوى محادثة، فقط طول الرسالة وتوقيتها).
- تطبيق الإدارة: شاشة "إدارة الإشعارات" (إنشاء إشعار بعنوان ومحتوى وجمهور مستهدف، حذف إشعار) — تُعرض الإشعارات المنشورة تلقائياً بالشاشة الرئيسية لتطبيق المستخدم.

## المرحلة 5 (لوحة الإحصائيات + إدارة المستخدمين + سجل التدقيق)

- لوحة التحكم الرئيسية بتطبيق الإدارة أصبحت تعرض أرقاماً حقيقية من قاعدة البيانات مباشرة (إجمالي المستخدمين، النشطون، المسارات، الدروس، الدروس غير المنشورة، عدد أسئلة الاختبارات، الدروس المكتملة) — ولا يوجد أي رقم وهمي.
- شاشة "إدارة المستخدمين": بحث بالاسم/البريد، تفعيل/تعطيل الحساب، منح أو سحب صلاحية مدير — بدون عرض كلمات المرور أو أي سر مصادقة. منح/سحب صلاحية المدير محمي بسياسة RLS فعلية على جدول `user_roles` (`roles_admin_only_write`)، فلا يقدر أي حساب غير مدير يكتب لهذا الجدول حتى لو تعدّلت الواجهة.
- شاشة "سجل تدقيق المدير": تعرض كل العمليات الحساسة المسجَّلة تلقائياً (إنشاء/تعديل/حذف/نشر محتوى، تفعيل/تعطيل حسابات، منح/سحب أدوار، تعديل الإعدادات) — بدون أي كلمات مرور أو أسرار بداخلها.

## المرحلة 6 (إعدادات المنصة + الإغلاق النهائي)

- شاشة "إعدادات المنصة": اسم التطبيق، الوصف، رابط/بريد الدعم، روابط سياسة الخصوصية وشروط الاستخدام، وضع الصيانة — محفوظة بجدول `app_settings` (قيم غير حساسة فقط؛ لا يُحفظ أي مفتاح أو سر بنية تحتية هنا، ولا تتوفر الشاشة طريقة لتعديل أي إعداد بنية تحتية حساس).
- تم توثيق أوامر البناء، التوقيع، ونشر Edge Functions لكل المراحل (أسفل هذا الملف).



## المرحلة 3 (الاختبارات + تتبع التقدم)

- **تم تشديد الأمان على جدول `quiz_questions`**: لم يعد بإمكان أي مستخدم عادي قراءة `correct_option` مباشرة من الجدول (كانت هذه ثغرة في مخطط المرحلة 1). القراءة الآن فقط عبر دالة `get_published_quiz_questions` التي لا تُرجع الإجابة الصحيحة إطلاقاً.
- **لم يعد بإمكان أي مستخدم كتابة `quiz_attempts` من التطبيق مباشرة** (كانت هذه ثغرة أيضاً تسمح بتزوير النتيجة). الكتابة الوحيدة المسموحة هي من Edge Function جديدة: `grade-quiz`.
- `grade-quiz`: تستلم إجابات المستخدم فقط (بدون أي درجة)، تجلب الإجابات الصحيحة بصلاحية الخادم، تحسب الدرجة، تكتب `quiz_attempts`، وإذا نجح المستخدم (حسب `pass_score` الخاص بالدرس) تُحدّث `lesson_progress` تلقائياً.
- أضيف عمود `lessons.pass_score` (افتراضي 70%) — يظهر في نموذج تعديل الدرس بتطبيق الإدارة.
- تطبيق المستخدم: شاشة اختبار الدرس (اختيار إجابة واحدة لكل سؤال) + شاشة نتيجة تعرض الدرجة والنجاح/الرسوب وتفسير كل سؤال، مع إمكانية إعادة المحاولة عند الرسوب.
- تطبيق الإدارة: شاشة إدارة أسئلة كل درس (اختيار من متعدد أو صح/خطأ)، تحديد الإجابة الصحيحة والتفسير، نشر/إخفاء السؤال — كل عملية تُسجَّل بسجل التدقيق.
- **ملاحظة مهمة**: نفّذ ملف `backend/supabase/migrations/0002_quiz_security.sql` بعد `schema.sql` إذا كان المشروع منشأً مسبقاً من المرحلة 1 أو 2، وانشر Edge Function الجديدة:
  ```
  supabase functions deploy grade-quiz
  ```



## المرحلة 2 (الشاشة الرئيسية + المسارات + الدروس)

- تطبيق المستخدم: شاشة رئيسية كاملة (ترحيب، نقاط، ملخص التقدم، قائمة المسارات، الإشعارات)، شاشة دروس كل مسار، شاشة تفاصيل الدرس (محتوى Markdown، الأهداف، رابط الفيديو، تفضيل/إكمال الدرس يحفظان في `lesson_progress`)
- تطبيق الإدارة: شاشة إدارة المسارات (إضافة/تعديل/حذف/نشر) وشاشة إدارة الدروس داخل كل مسار (كل الحقول المطلوبة + حفظ Markdown)، وكل عملية حفظ/حذف/نشر تُسجَّل تلقائياً في `admin_audit_logs`
- كل الكتابة من تطبيق الإدارة محمية بسياسات RLS للمدير فقط (`public.is_admin()`)، فحتى لو تعدّلت شاشة الإدارة، الخادم يرفض أي كتابة من حساب غير أدمن



تم في هذه المرحلة بناء:

- هيكلة تطبيقين منفصلين: `cyber-iraq-app` (المستخدم) و `cyber-iraq-admin` (الإدارة)، بمعرّفي حزمة مختلفين:
  - المستخدم: `com.cyberiraq.app`
  - الإدارة: `com.cyberiraq.admin`
- قاعدة بيانات Supabase كاملة مع RLS: `backend/supabase/schema.sql`
- Edge Function للمدرس الذكي (مفتاح الـ API يبقى على الخادم فقط): `backend/supabase/functions/ai-tutor/index.ts`
- شاشات تسجيل الدخول/إنشاء حساب/استعادة كلمة المرور لتطبيق المستخدم
- شاشة دخول المدير لتطبيق الإدارة (تتحقق من دور `admin` من جدول `user_roles` على الخادم، وليس من أي قيمة يرسلها التطبيق)
- GitHub Actions لبناء APK للتطبيقين

## إعداد Supabase

1. أنشئ مشروع Supabase جديد.
2. شغّل محتوى `backend/supabase/schema.sql` كاملاً من SQL Editor.
3. سجّل حساب المستخدم الذي تريده مديراً عادياً من خلال تسجيل الدخول العادي (Sign Up) — عبر تطبيق المستخدم أو من Supabase Auth مباشرة.
4. من SQL Editor نفّذ:
   ```sql
   select public.bootstrap_first_admin('admin@example.com');
   ```
   هذا يعمل مرة واحدة فقط طالما لا يوجد مدير حالياً، فلا يمكن استغلاله لترقية حساب عادي لاحقاً.
5. للتطوير فقط: أنشئ حساب Auth بالبريد `kali@admin.cyberiraq.local` وكلمة مرور `kali`، وامنحه دور admin بنفس الطريقة، ثم عطّله قبل النشر.

## إعداد المدرس الذكي (Edge Functions)

```
supabase functions deploy ai-tutor
supabase functions deploy grade-quiz
supabase secrets set AI_API_KEY=sk-...
```

لا تضع `AI_API_KEY` في أي ملف داخل تطبيق Flutter أو في Git. `grade-quiz` لا تحتاج `AI_API_KEY`، تحتاج فقط `SUPABASE_SERVICE_ROLE_KEY` المتوفر تلقائياً داخل بيئة Edge Functions.

## ترتيب تنفيذ ملفات SQL

نفّذهما بالترتيب من SQL Editor:

```
backend/supabase/schema.sql
backend/supabase/migrations/0002_quiz_security.sql
```

## متغيرات البيئة (غير سرية على الكلايント، anon key محمي بـ RLS)

عند البناء المحلي أو في CI مرّر:

```
flutter run \
  --dart-define=SUPABASE_URL=https://xxxx.supabase.co \
  --dart-define=SUPABASE_ANON_KEY=xxxx
```

أضف `SUPABASE_URL` و `SUPABASE_ANON_KEY` كأسرار GitHub Actions (Settings → Secrets) ليستخدمها ملف `.github/workflows/build.yml`.

## توقيع APK (Release)

لم يُضَف ملف `key.properties` فعلياً (لا يُرفع إلى Git). لتوليد توقيع حقيقي:

```
keytool -genkey -v -keystore cyber-iraq.keystore -alias cyberiraq -keyalg RSA -keysize 2048 -validity 10000
```

ثم أنشئ `android/key.properties` في كل مشروع (محلياً فقط، أو كسر GitHub Actions) بالمحتوى:

```
storePassword=...
keyPassword=...
keyAlias=cyberiraq
storeFile=../cyber-iraq.keystore
```
